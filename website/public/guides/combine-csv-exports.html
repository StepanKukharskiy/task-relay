Combine recurring CSV exports into one checked report

A recurring report should not start with another round of copy-paste. Use one checked transformation and keep a record of where every row came from.

A request to combine exports from five tools describes both the repetitive work and the failure of an existing approach at larger sizes. This guide starts with a small, reproducible version.

The example

Two CSVs contain four rows, including one identical repeated record. The recipe returns three unique records totaling EUR 37.30, plus a receipt linking each record to its source file and row.

Download the sample and script

Choose the rules before merging

This sample expects five columns: record_id, date, customer, amount and currency. Column order may differ. Dates use ISO format, amounts have at most two decimal places and currency codes use three capital letters.

record_id is globally unique in this example. An identical repeated record is counted once, with both sources preserved in the receipt. Two different records with the same ID stop the run. For exports whose IDs are only unique within each tool, establish a source-qualified key before using this recipe.

Run the sample

Extract the ZIP and open its csv-sample folder. Python 3.11+ is sufficient; this command uses the standard library.

python3 file-recipes.py csv-merge input output

Open output/combined.csv and output/receipt.json. Confirm four input rows, three output rows, one duplicate and the EUR 37.30 total. Totals remain separate for different currencies.

Ask Task Relay to handle the repetition

Select a project containing the files and a worker that can run local commands. Send:

Use the checked file-recipes.py CSV recipe on the files in input.
First confirm that their schema and record IDs match the documented rules.
Write to a new output folder. Return the combined CSV, row reconciliation,
totals by currency and the receipt. Stop and explain any conflicting ID.

For your own exports, start with representative files and a precise column mapping. Have the worker preserve the mapping as a reusable script and review its first result. Avoid guessing which column is an ID or silently dropping a changed field.

Check a repeat run

  • Input rows equal unique output rows plus duplicate rows.
  • Totals use decimal arithmetic and remain separate by currency.
  • Every output record has source lineage.
  • The receipt identifies the output bytes and the input versions.

An unexpected schema, invalid amount or conflicting duplicate stops before creating an output folder. An interrupted folder must be inspected; rerun into a new folder after resolving the cause.

Verification: the downloadable synthetic example reconciles correctly. Controlled checks cover conflicts, schema drift, formula-like spreadsheet text and symbolic-link inputs. Large-file performance and the installed Relay delivery path have not been benchmarked.

Try it with your own task

Set up Task Relay, connect a suitable worker and begin with a small representative input. Review the first result before repeating the workflow.
