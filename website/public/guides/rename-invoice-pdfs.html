Rename invoice PDFs from their contents

Stop opening every invoice just to give the file a useful name. Extract the fields once, review the proposed names, then create named copies.

Requests for bulk invoice naming often start with the same problem: a download called download-01.pdf tells you very little about its contents.

The example

The sample contains two synthetic, text-based invoices. One becomes Example-Studio-2026-09-01-INV-100.pdf. The original PDF stays unchanged. A receipt records the original filename, new filename and file hash.

Download the sample and script

What you need

  • Python 3.11 or newer and pypdf in the worker's Python environment.
  • A folder of downloaded PDFs with selectable text.
  • A naming rule and field patterns appropriate to those invoices.

The sample recognizes the labels Vendor:, Date: and Invoice:. For another layout, have your worker inspect a representative file and adapt patterns.json. Scanned documents need an OCR step before this recipe.

1. Prepare and review the names

Extract the ZIP and open its invoice-sample folder. Install pypdf into your chosen environment if needed. Run:

python3 file-recipes.py invoice-preview input patterns.json plan.json

Open plan.json. Check the vendor, ISO date and invoice number against the PDFs. Missing fields, conflicting matches and filename collisions are marked for review. Resolve these by correcting the patterns or separating input batches, then generate a fresh plan.

2. Create the named copies

python3 file-recipes.py invoice-apply input plan.json output

Use a new output directory. The script checks that the inputs still match the preview before copying. It refuses an existing output folder. A receipt.json with status: complete marks a finished run; a folder without that receipt needs inspection before another attempt.

Run it through Task Relay

Choose a project containing the extracted sample and a connected worker with file and command access. Send:

In this project, use file-recipes.py and patterns.json to preview names
for the PDFs in input. Return the plan and any exceptions for my review.
Keep the originals unchanged. Wait for my choice before creating copies.

After reviewing the returned plan, ask the worker to apply that exact plan to a new output folder and return the receipt and named files. Direct text-only provider connections cannot execute this script.

Use it again

Reuse the checked script and patterns with another batch from the same invoice layout. Review any new exceptions. Keep each batch's plan and receipt so a correction can be traced to the original document.

Verification: the script copied both synthetic PDFs without changing their bytes. Controlled checks cover changed inputs, missing fields, collisions and existing partial output. The installed Relay/provider/messenger path still needs its own run; no end-to-end time saving is claimed.

Try it with your own task

Set up Task Relay, connect a suitable worker and begin with a small representative input. Review the first result before repeating the workflow.
