Repeat a precise model edit in Rhino

Apply the same dimension change to selected objects, keep the rest of the model intact, and review a new .3dm version.

The problem people report

McNeel users describe resizing dozens of objects to the same height while preserving their widths, with later replies discussing furniture modules and a script workaround. A separate user asks about setting object dimensions through Python. These are concrete examples of repeated dimension edits. The historical BoxEdit discussion is not a claim that its bug persists today.

Start with one clear change

You provide: the exact .3dm, target object names or IDs, units, target dimension, fixed anchor and what must remain unchanged. Start with a few simple objects. Use installed and licensed Rhino 7 or 8 on macOS, plus a worker able to prepare and review Rhino Python.

You get: a candidate .3dm, viewport preview and checks against the selected source and requested dimensions. You choose whether the candidate becomes the next version.

Before you start

These instructions are matched to the capabilities bundled in Relay 0.13.24, checked on 15 September 2026. The website download is still 0.13.0-beta.1; it does not establish availability of this whole workflow. Ask your running Relay to check the required tools before starting.

Use a configured worker to prepare and review the work. Select the exact input files, review the proposed plan, then press Start. For model edits, Relay prepares the code first and asks you to approve that exact code before running it in the local app.

Give Relay this request

Inspect this selected .3dm and identify [object names or IDs].
I want each object's world-Z height to be [value and units], keeping its
base elevation and X/Y dimensions unchanged. Preserve all other objects,
layers and materials. List ambiguous targets before preparing an edit.
Prepare the Rhino-compatible script and checks, then stop for review.
After I select the exact script, checks and source model, propose the host
execution plan. Save a new candidate .3dm, reopen it independently and
return dimension/preservation checks and a viewport preview.

Review the edit before running it

  1. Check the inspection: correct version, units, object selection and orientation.
  2. Review the prepared change and checks. Scaling a bounding box is suitable for simple study geometry; it may distort detailed parts.
  3. Approve the exact script and source model in the execution plan. The script runs with the local app's normal host permissions.
  4. Check the candidate dimensions and preview, then select or reject it. Reuse the request with a newly selected model for the next revision.

The same route can create a new model from an explicit geometry brief. That is a separate prepared script with its own checks. Grasshopper execution is not part of this guide. A viewport preview is not a finished render; use named-view rendering when you need presentation images.

Capability check: rhino.inspect and rhino.run_python are present in the audited app bundle. See the operation documentation for implementation scope and recorded checks. This article is a workflow recipe; its exact prompt has not been qualified through a complete live Relay run. Forum reports establish a problem, not measured time savings.
