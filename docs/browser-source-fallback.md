# Provider-neutral public browser fallback

`web.sources.rendered` consumes an exact `public_source_candidates` pack from any
registered search provider. The existing compiler can compose it from a freshly
frozen available `observed-public-page-rendering-fallback` companion relationship.
It does not add the capability to existing owner grants. Direct/native use remains
available within an explicitly admitted operation graph. No provider-specific
recovery agent or per-publisher extractor is required.

Code selects bounded literal observed failed URLs and HTML candidates lacking a
rendered observation. Price presence is not a completeness criterion. The host
receives the intersection of original and selected domains before navigation.
No new search, invented URL, account adoption, form submission or automatic
challenge resolution occurs. Full workflow authorization and capacity remain
with the existing compiler/controller.

A durable source-hash/selection manifest and exclusive per-read intents precede
external reads. Original evidence is preserved; confirmed browser observations
are appended with target mappings and provenance. Confirmed receipts can be
reused after restart; changed or missing proof cannot authorize replay. Previously
attempted URLs remain in the source-pack ledger and are not implicitly retried.

The current host adapter uses an isolated unsigned-in browser, bounded visible-DOM
settlement and retained DOM/text hashes. It records navigation status and keeps
access-denied/challenge/empty captures as diagnostics instead of usable source
pages. A cleanup failure cannot erase an already confirmed capture. Stability is
not semantic completeness, and title-based challenge detection is intentionally
limited. Independent review still judges correspondence and factual support.

The public-source host uses Chromium-native navigation through
`public_browser_navigation`, rather than refetching the main response through a
request API. A request-stage guard checks public URL/DNS, read methods and main
navigation domains, including redirect hops, before continuation. The context is
Relay-owned; attached user browsers are refused. Background POSTs, downloads,
WebSockets and unowned tabs remain blocked. The guard is bounded to 1,000 requests
and retains network diagnostics; its module hash is frozen and checked before
dispatch. Missing or replaced documents are retried within the existing observation
window. Closed pages and other failures still stop. These are host mechanisms,
independent of the model or search provider.

## Explicit native browser authority

`web.sources.native` consumes and returns the same exact source-pack interface.
It composes the existing collector and native computer-use journal; it does not
add a scheduler or model provider. Parameters select `browser: safari-visual`,
1–3 pages and 2–8 observations per page. The collector chooses only literal
observed public URLs within the original/selected domain intersection.

This authority differs from isolated rendering: Safari uses its normal session
and page-generated network requests. The fixed helper can create a dedicated
foreground window, observe the exact URL and scroll; no click, form, login,
upload, download or arbitrary script surface is supplied. It is not a network
firewall. Existing isolated grants never silently gain native access. The new
operation must be admitted explicitly. The native helper and implementation are
frozen before dispatch; permissions and identity are checked before opening a
window. `TASK_RELAY_COMPUTER_HELPER` is an optional host configuration path to an
already verified helper, not a model parameter. Packaged runs use the bundled
helper by default. No helper is compiled or permission granted automatically.

The registered resource is the existing `computer-safari`, and execution also
uses the host lease. All actions use the existing committed native journal,
ownership controls, target/token checks and uncertain non-replay rules. Each
original request/response and visible-text observation is retained. Scrolling is
bounded; a no-effect refresh or final viewport never proves complete page coverage.

A confirmed failed read by another transport may be selected under the new native
grant. Policy identity is part of the collection receipt. Same-policy reads are
not repeated, successful earlier evidence is preserved, and uncertain operations
are never replayed. Confirmed native receipts can be reused without reopening a
browser. Native captures identify their transport, observation IDs and text basis;
they do not claim HTML, image metadata, purchasing completeness or acceptance.

Actual qualification on the previously denied merchant page succeeded through the
registered visual Safari operation: eight real observations contained name, price,
dimensions and material text. Original entries were unchanged and exact saved
results were reused without browser calls. The host reader/helper matched the live
frozen assignment; the final scheduler-resource declaration was qualified offline.
66 affected checks passed, followed by 9 focused checks (8 overlapping). Background
Safari creation timed out and remains separately unqualified; no retry or transport
switch repaired that original attempt. The Chrome background-POST experiment still
received server denial and did not change the production isolated-reader policy.

## Owner handoff and composed cancellation

The existing owner catalog/delegation interface can select the native operation
after inspecting a confirmed isolated-reader failure, when both operations are
already in its frozen grant. The collector retains successful reads and all prior
entries; the newly granted reader selects remaining eligible URLs. No automatic
grant expansion, new selector/controller or site-specific retry rule is required.
Code binds the combined source version to downstream work and independent review.

Operation cancellation now reaches the nested native session and its helper
ownership controls. A native pause, stop or takeover stops the entire collection,
not just that page. The collector saves a durable stop receipt and refuses to
resume reads after the cancellation file is removed. Confirmed raw responses stay
available. Unresolved actions take precedence over cancellation: they remain
uncertain and cannot produce a completed source pack or unblock a dependent task.
An acknowledged stop produces a confirmed failed operation receipt with no output.

Offline qualification exercises a scripted owner through the real compiler,
scheduler, registered collectors, native journal and worker/reviewer tool loops:
isolated denial plus another successful page, explicit native handoff, two runtime
restarts, retained exact evidence, report composition and independent final review.
It also checks missing authority, insufficient capacity, cancellation before and
after dispatch, pause/takeover, foreground loss and uncertain upstream blocking.
68 affected tests passed. Provider decisions and native observations were synthetic;
this does not prove live Codex route selection or complete workflow quality.

## Current increment — shared execution review and bounded recovery

Text/JSON inspection requirements no longer imply pixel review. Prospective
`execution_review_version:1` grants expose exact operation provenance through the
same capsule for standalone consumers/reviewers and in-worker `work_evidence`.
Capsules bind original admission, input/output identities, completion receipts and
registered adapter evidence. Completion seals the adapter evidence hash; changed
journals reject. Derived context files have inspection-only roles, never operation
inputs or final deliverables. Native helper build metadata stays distinct from
confirmed live actions; success still requires independent semantic review.

Owners can report a terminal blocker with `job_stop`; code stops further proposals
and lets existing settlement drain dispatched work. Unchanged failed snapshot
reviews stop at admission, while new evidence/candidates can be reviewed. Repeated
failed completion is counted across owner invocations, independent of summary
wording. Exact completed-producer and final acceptance checks are retained.
