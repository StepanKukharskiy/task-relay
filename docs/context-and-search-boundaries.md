# Stable owner context and independently configured tool providers

Installed as 0.13.225 on 2026-10-11 after exact-package controlled qualification.
Live efficiency and unattended deck completion remain unverified.

## Context projection

The shared working view must remain stable when its output is checkpointed and
restored. Previously, a semantic view could become a quoted note inside another
semantic view. Repeated escaping enlarged history. Retention also measured the
original protocol messages instead of the representation ultimately submitted.

`WorkingView.retained` preserves already projected observation messages verbatim.
They remain untrusted data, never instructions or acceptance. Other exchanges
are projected once, and selection measures those actual projected bytes. The
latest complete tool exchange remains intact. Omitted exchanges retain exact
archives; oversized required state or the latest exchange still fails before
dispatch. No context ceiling, model allowance or original journal is changed.

## Agent model versus tool provider

Relay owns search orchestration, public HTTPS retrieval, parsing, URL identity,
capture deduplication and evidence handoffs. Search-result discovery still needs
a search provider. Selecting Codex for the owner does not inherently require
Codex to perform every retrieval.

Trusted job admission can capture `operation_backends`, mapping granted registered
operations to exact provider/model profiles. The shared model-binding boundary
fills tool-owned model parameters and hides them from owner choices. Native
dispatch uses that tool profile; owner, content workers and independent reviewers
keep their own authorized profiles. Provider configuration and model availability
are checked before search. Credentials are not copied into grants or prompts.

For example, a Codex owner can use the existing `web.sources` Google-grounded
search adapter with an explicitly authorized Gemini tool profile. This retains
Gemini billing for search; it is not subscription-only execution. Without that
explicit grant, Codex-only jobs still reject foreign model-backed operations.
Continuations cannot silently change tool profiles. This uses the existing
compiler, controller, source collector and review flow, not a second scheduler.

Registered Gemini source collection asks for URL discovery rather than product
comparison or a report. It preserves the exact request and raw response. Code
consumes recorded grounding, fetches pages, filters domains and reuses exact
captures; prose URLs are not evidence. Agent-facing ad hoc search retains its
existing synthesis behavior. The request/output ceiling is unchanged. A shorter
instruction is not a measured token-saving claim.

## What the subscription CLI exposes

The installed CLI's freshly exported stable and experimental client-RPC schemas
have no dedicated direct public-web-search method. `mcpServer/tool/call` executes
a separately configured MCP tool; it is not a subscription web-search endpoint.
The documented `webSearch` item is an agent-issued search inside a generation
turn. Official references:

- [App-server lifecycle and webSearch items](https://learn.chatgpt.com/docs/app-server)
- [ChatGPT-plan route limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

These observations do not establish a model-free subscription search API. The
existing Codex search adapter remains available, with its internal request count
and any unreported usage explicitly unknown. No private endpoint, token extraction,
forced model change or unverified cancellation shortcut was introduced.
