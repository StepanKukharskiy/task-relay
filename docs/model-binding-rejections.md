# Model authority and confirmed provider rejection

Adapters may declare `backend_binding` for model and reasoning parameters. The
owner catalog exposes semantic inputs, and the compiler fills bound fields from
the authorized job backend. Historical model proposals remain in the tool/event
journals. Native assignment freezing and execution verify the binding. The
registered Codex source variants use this contract; adding another compatible
adapter does not require another owner/controller path. Model identities for
different modalities are not inferred from an unrelated text backend.

The CLI worker and search transport use the same terminal-rejection proof. It
requires one dispatched thread/turn, a matching non-retrying structured client
error, its failed terminal event, and no tool request or executable item. A
missing/partial journal, foreign identity, server error, tool effect or ambiguous
termination remains uncertain. This proof establishes rejection, not zero usage.

Search receipt inspection can reconcile an earlier misclassified rejection from
those immutable journals. It keeps the original receipt and proof in the normal
controller event/attempt history; no raw receipt is overwritten or request
replayed. Any replacement work still consumes remaining frozen capacity. A
prospective continuation preserves accepted artifacts and the predecessor grant
through the existing inheritance admission, without making the old assignment
look as if it ran under new code.

Qualification includes normal registered source collection, owner delegation,
worker/search rejection, read-only legacy reconciliation, owner correction,
ambiguous-effect holds, and the existing build/inspect/correct/review flows. The
exact live proposals and HTTP 400 event are replayed separately without model
calls. Package and deployment evidence is in
`private qualification records`; controlled replies do not
establish live completion or source quality.
