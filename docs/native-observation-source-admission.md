# Native observation and committed source admission

Registered source availability is established by the exact committed operation,
including when a containing worker subsequently stops. The shared committed-output
reader verifies the frozen assignment, latest inline version, input/output hashes,
terminal operation and materialization receipt before exposing source provenance.
Active or uncertain producers are excluded. A stopped worker's authored JSON is
not a source receipt. This proof does not accept the worker or its content.

The macOS host adapter bounds pure observation settling within the existing session
deadline. It rechecks window, selected tab, document and text stability on every
read. The frozen same-origin navigation policy can bind a late observed URL only
after window/tab checks; it never reissues navigation or grants another origin.
Known exhausted read failures carry an exact target, URL, operation, session token
and explicit no-action marker. The shared host journal admits only correlated
read-only failures, retaining the request, rejection and earlier captures. Missing,
malformed, stale or effectful responses remain uncertain. Confirmed failures may
let the existing source collector continue other bounded candidates; they do not
increase source caps or retry allowances. Cancellation/ownership controls remain.

Qualification uses synthetic observations through actual registered operations,
compiler admission, worker protocols, restart and review. Native settling and URL
policy are compiled with controlled closures; building the full helper verifies
integration compilation, not live page availability. Original uncertain outcomes
remain uncertain; this contract applies prospectively to newly pinned helpers.
