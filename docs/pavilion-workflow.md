# Cellular pavilion workflow

Open `examples/cellular-pavilion.workflow.json` using Relay's existing workflow
import format, or use the saved Cellular pavilion draft. Its nine visible nodes
use the same runtime and operation definitions as the editor.

1. Codex writes a deterministic cellular-automata Blender Python script.
2. A separate bounded preparation supplies the registered scene checks.
3. Blender Python builds, saves, reopens and previews the approved script result.
4. Export Blender geometry reads the exact .blend and outputs evaluated world meshes.
5. xFigura takes the Blender PNG and the rendering prompt.
6. Drawing preparation consumes the exported mesh, not the visualization.
7. Rhino builds the prepared plans, sections and elevations.
8. Presentation preparation combines script explanation and the three views.
9. PowerPoint export creates the PPTX.

The default brief is a conceptual 6×6 meter pavilion. Edit it before execution.
Dimensions are design inputs, not engineering certification. Generated render
images do not establish geometry preservation or construction suitability.

Blender `scene_sha256: null` selects creation; legacy hash bindings remain supported.
New wires use runtime-bound paths despite the compatibility parameter names.
Creation checks declare `mode: create`, `units: Meters`, all object names, an empty
`changed_objects`, dimensions and preview settings. The preparation code supplies
the preservation flags. Existing edit contracts still forbid object additions.
Exact-script approval binds the completed script/check bytes, application and
assignment before host execution. Preparing or saving a graph is not approval.

xFigura needs a signed-in saved Chrome profile and the URL of a selected **empty**
render node. Its currently supported DOM boundary is the selected React Flow node,
with one file input, prompt field, Generate control and an original PNG download
link. It does not construct xFigura's internal canvas, overwrite an existing render,
purchase credits or fall back to screenshots. If the current website differs,
it stops; passing synthetic DOM checks is not live site qualification. Each
run may spend account credits and requires paid confirmation. No automatic retry
is allowed after a generation or uncertain upload/download.

Offline qualification uses a deterministic rule-90 script, real local Blender,
exact mesh projection into the Rhino drawing contract, a controlled drawing raster
and real local PPTX creation/reopening. Browser actions and errors use synthetic
pages; native Rhino and unscripted model decisions are not proven by this fixture.
