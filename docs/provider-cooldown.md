# Bounded provider cooldown

A prospective `provider_cooldown` owner grant enables the shared generation admission policy. Version 1 permits two continuations after correlated temporary rejection, with 30 and 90 second minimum delays and a cumulative 180 second wait allowance per assignment. Existing provider exchange, tool, attempt and elapsed-time budgets remain authoritative. A longer valid Retry-After is honored only if it fits; otherwise execution stops. Quota/spend exhaustion is not a temporary-retry grant.

The runtime freezes the trusted run-local SQLite location into every assignment and nested registered source operation. Workers using the same provider/model share an atomic next-admission time. After a cooldown, resumed calls are separated by two seconds to avoid a simultaneous burst. This coordination is limited to the run; it does not govern other applications or account traffic. Native/local work is not subject to this provider gate, though existing concurrency slots still apply to waiting workers.

Confirmed function-only generation rejection can continue without repeating tools. Earlier context, committed artifacts, outputs, observations and decisions remain in the original assignment and persistent Codex thread. Codex proves the exact failed thread/turn, all preceding dynamic acknowledgments, and absence of unknown native/hosted effects. Structured exhausted 429/503 and server-overload terminals are supported. Other providers use their function-only synchronous transport contract. Missing replies, pending effects, hosted generation and explicit quota exhaustion remain held. Enabled cooldown replaces immediate error retry for these assignments; it does not authorize transport-uncertain replay.

Wait state and consumed allowance persist across coordinator/scheduler reopening. A cancellation or insufficient remaining time stops before recording a pending request. Every eligible rejection records original request/outcome hashes, ordinal, next admission time, remaining budgets and non-acceptance. Append-only Codex journals are bound by exact prefix lengths and hashes so later turns preserve verifiable rejection evidence. Retry admission commits before external dispatch. A process crash is not permission to start an uncertain worker or submission again.

Registered searches participate in the same cooldown but retain their fixed operation allocation. A confirmed failed search cools peers without granting another search submission; the source collector preserves earlier pages and marks unresolved/unsubmitted queries honestly. Unknown search effects are never replayed. This policy does not manufacture evidence, force browser fallback or accept a deliverable.

Controlled checks and live qualification are recorded separately in `private qualification records`. Passing synthetic boundaries does not establish service recovery or full artifact quality.
